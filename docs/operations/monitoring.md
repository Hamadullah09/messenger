# Monitoring, Alerting and Tracing

## Local stack

```bash
docker compose --profile monitoring up -d     # Prometheus :19090, Grafana :13000 (local only)
```

Prometheus scrapes the API (`:9464`) and worker (`:9465`) metrics endpoints on the host.
Grafana provisions the **SMA — Operations overview** dashboard
(`infrastructure/monitoring/grafana/dashboards/sma-overview.json`, generated by
`scripts/monitoring/build-dashboard.cjs`) and the Prometheus data source. Change Grafana's
initial admin password on first sign-in.

## Metrics endpoints

`/metrics` is served on a separate internal port (`METRICS_PORT` 9464 for the API,
`METRICS_WORKER_PORT` 9465 for the worker), bound to `METRICS_HOST` (loopback by default),
optionally protected with `METRICS_TOKEN` (bearer). It is never exposed on the public API
port. Labels are bounded: route templates (never raw paths), event types, outcomes, permission
keys and audit action names — no user ids, tenant ids or content.

| Requirement | Metric(s) |
| --- | --- |
| API request rate, latency, errors | `sma_http_requests_total{method,route,status}`, `sma_http_request_duration_seconds` |
| WebSocket connections, reconnections | `sma_websocket_connections`, `sma_websocket_connects_total` |
| Message acceptance | `sma_messages_accepted_total{kind}` |
| Queue depth, DLQ size | `sma_queue_jobs{queue,state}`, `sma_outbox_pending`, `sma_outbox_failed` |
| Processing latency | `sma_delivery_latency_seconds{type}`, `sma_outbox_oldest_pending_seconds` |
| Delivery success/failure, retries | `sma_delivery_jobs_total{type,outcome=success|retry|dead_letter}` |
| Database pool / query latency | `sma_db_connections`, `sma_db_query_duration_seconds` |
| Redis latency / availability | `sma_redis_up`, `sma_redis_ping_seconds` |
| Upload / download throughput | `sma_media_upload_bytes_total`, `sma_media_download_urls_total` |
| Media-processing failures | `sma_media_processed_total{outcome}`, `sma_media_verifying` |
| Storage consumption, tenant quota | `sma_storage_bytes`, `sma_tenant_storage_usage_ratio_max` |
| Campaign progress | `sma_campaigns_sending`, `sma_campaign_pending_recipients`, `sma_campaign_messages_written_total`, `sma_campaign_batch_duration_seconds` |
| Emergency acknowledgement latency | `sma_emergency_ack_latency_seconds`, `sma_emergency_awaiting_ack`, `sma_emergency_overdue_seconds`, `sma_emergency_escalations_total{result}` |
| Authentication failures | `sma_auth_login_failures_total{step}` |
| Authorization denials | `sma_authz_denials_total{permission,reason}` |
| Administrative actions | `sma_audit_events_total{action,outcome}` |

Backlog gauges (queues, outbox, incidents, campaigns, storage, DB connections, Redis) are
computed at scrape time by the **worker** only (cached 5–10 s), so they are reported once per
deployment.

## Alerting

19 rules in `infrastructure/monitoring/alerts.yml` (validated with `promtool` in CI), grouped
as availability, delivery, emergency, data and security. Thresholds and first responses are in
the [runbook](runbook.md#alerts--actions). Route `severity=critical` to paging and
`severity=warning` to the team channel (Alertmanager configuration is environment-specific).

## Tracing

OpenTelemetry tracing turns on when `OTEL_EXPORTER_OTLP_ENDPOINT` is set (OTLP/HTTP,
`/v1/traces`), for both processes (`sma-api`, `sma-worker`; override with
`OTEL_SERVICE_NAME`). Instrumented: incoming/outgoing HTTP (health and metrics requests
excluded, query strings dropped), Express routes and Redis commands (command names only, no
arguments). Request and response bodies and headers are not recorded. Logs carry the
`X-Request-Id` for correlation. Verified locally by exporting to a test OTLP receiver.

## Logs

Structured JSON (pino) with request ids; authorization headers, cookies, passwords, tokens
and contact fields are redacted. Ship stdout to the log platform; retain 30 days (security
events in the audit log are retained per policy).
